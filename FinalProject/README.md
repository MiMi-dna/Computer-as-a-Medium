**FPS Narrative Idea:** 
Earth had colonized Mars successfully but those that were able to make the move to the Red Planet seceded almost as soon as the colonizers were able to establish themselves. Those in power weren't prepared for the lonely harshness of dealing with the new environ without Earth's resources. Over time, the Martians who remained fled to the dead space Freighters still hovering around like space trash. Through ingenuity many of these freighters were combined into large shipyards forming small communities. After centuries, first-contact to Alien life was achieved and Earth reclaimed Mars, leaving the first-generation Martians and their kin to fend for themselves shipyards. You are one such Martian - finding yourself on a small rag-tag group of scavengers, you're looking for another safe hub or a satellite facility that no one's going to miss when you guys take it down and strip it for whatever resource you can find.  

This game scene would be your first scavenge attempt - a demo or introductory stage that introduces players to the controls of the game that they will be implementing for the rest of gameplay

**Major Modification Scripts:** 
AugmentStamina.cs and AugmentStaminabar.cs, both were implemented with PlayerController.cs and GameManager UI related scripts
- Users can now use the Sprint button to run faster at a multitude based on the player characters defined movement * the augmented Speed. With the implication that the script can be used and modified if other "augments" are applied or if there are other playable character that are added with alt stats. The increased augmented speed is tied to a Stamina Bar available in the UI that decreases as the player character holds onto the Sprint button. If the bar depletes, the character reverts to walking speed. If they manage to toggle playing with the Sprint action (not letting it deplete entirely), they can continue at a higher-than-normal Sprint speed.

**Minor Modification Scripts:** 
EnemyController.cs and PatrolPath.cs, utilized the script on 3 bot enemies to manage individualized pathing and increased stats to the blue bot
- I mostly used what already existed in terms of the script design and made most of my modification choices for behavior in how I implemented the EnemeyController and PatrolPath script. The mindless floating kill bot action fit my narrative for an introductory level, so I wanted to keep the patrolling behavior but extend the ability to patrol to all the bots, each one having its unique pathway, with the blue bot being a bit stronger and faster than the other bots. 

I slightly modified all related FPS code to ensure the audio and door trigger scripts matched my needs a little bit better but otherwise most of the scripts remained the same. I used the existing script to push and learn more about how to manage adding/implementing my new scripts with the existing ones without breaking the existing scripts.

**Challenge:**
I specifically chose the challenge to implement a new script into existing architecture because I feel like that may be more in line with how we might be introduced into the field - accessing and implementing art or code design within an existing project. I feel that learning to read someone else's code, understand their choices, and use that knowledge to implement new code or refine the existing code could be a good skill to have. But this created a lot of challenges as I had to adhere to a structure and syntax that I'm unfamiliar with. For example, this was the first time I encountered the use of an "m_" prefix variable standard and new types of class/inheritance style types like "namespace". Outside of the project itself, I found it difficult to decide on how I wanted to organize my files and constantly kept asking myself if a code was too long or complicated for what industry standards might be. I am sure I will feel better about this when I am able to work in the field but at the end of this project, I feel a bit better about what some of my scripting design choices should be.
